## 本轮结果

| 工作面 | 实现结果 |
| --- | --- |
| 审批续跑 | 持久化对话中的未回应工具调用按原顺序继续执行；逐项批准或拒绝，保留后续草稿和审批，已完成调用不重复执行。 |
| 执行审计 | 每次模型调用记录步骤；审批后继续遵守本次运行的轮数上限。取消会关闭待执行步骤和调用，模型返回后检查取消状态。 |
| 我的工作 | 服务端新增运行中、待审批队列，保留待处理、受阻、等待他人、最近完成的既有语义，完成任务留在历史。 |
| 运行缓存 | 工作区共用运行缓存，组合最近历史与全部活跃运行；单任务历史独立缓存并合并到共享视图，手动刷新可重取历史。 |
| 实时恢复 | 合并单运行快照、去重、按序号补拉；先应用补拉得到的最新快照，再推进消费序号。刷新失败保留当前实时状态，过期请求不能覆盖新结果。 |
| 多人更新 | 没有来源频道的运行向当前工作区成员发送更新；有来源频道的运行继续沿频道和发起人订阅发送。 |
| 运行详情 | 集中展示状态、步骤、来源、审批和可展开的产物，支持原因输入、批准、拒绝、取消、重试和读取失败恢复。 |
| 工作区管理 | 角色管理移出任务页，提供桌面导航和手机工具入口；请求代次守卫覆盖 A→B→A，角色更新同步成员状态。 |
| 主题 | 明暗主题显式指定正文和标题前景色，统一控件字体，修复浅色主题继承默认白色文字的问题。 |

活跃运行查询新增兼容参数：

```text
GET /api/v1/workspaces/{workspaceId}/agent-runs?activeOnly=true&limit=200
GET /api/v1/workspaces/{workspaceId}/agent-runs?activeOnly=true&limit=200&afterId={lastRunId}
```

活跃页按稳定运行 ID 排序，单页最多 200 条。原有列表、状态筛选和任务筛选继续可用；`activeOnly` 与 `status` 分别使用。客户端负责补齐全部活跃页，任务队列不受最近 50 条历史记录的窗口限制。

本轮沿用现有数据库表与增量迁移，新增的步骤、事件和工具取消状态保留既有记录。项目原有未提交改动作为实现基线。
